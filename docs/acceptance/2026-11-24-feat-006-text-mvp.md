### 1.1 身份来源（对应第 1、3 行）

正式接收链路的身份不是从 CPB/response UID 猜出来的，也不是 resolver 映射的：

- bridge 只发送已通过 `WrapperMessageEnvelope::validate` 且绑定匹配的 wrapper 记录，wire 投影字段保持
  `None`（[daemon_client.rs](../../crates/caligo-bridge/src/daemon_client.rs) 的 `event_payload`）。
- core 用 wrapper 记录的 `peer_uin`/`sender_uin`/`msg_id`/`msg_time` 建立持久身份与
  OneBot 兼容投影（[message_store.rs](../../crates/caligo-core/src/message_store.rs) 的
  `insert_wrapper_event`、`projection_for_event`），再由
  [daemon.rs](../../crates/caligo-core/src/daemon.rs) 的 `publish_onebot_message` 生成标准事件。
- 离线回归 `wrapper_message_chain::d8_owned_records_reach_journal_and_only_current_incoming_messages_fan_out`
  同时断言三件事：`event_payload` 的 `onebot_projection` 为 `None`、`get_msg` 能按持久 ID 读回同一正文、
  两个 SSE/WS 订阅者收到同一份带 `self_id`/`user_id`/`time`/`font` 的标准事件。
- 现场侧，2026-11-14 的私聊与登记群文本样本已经用同一链路取得 SSE、持久账本和 HTTP `get_msg`，
  `get_msg` 的消息 ID、类型、发送者与正文和事件一致；双账号 LoginInfo 的账号/昵称与独立资料卡一致。
  见[登记测试群回读](../execution/2026-11-13-snowcat-capability-integration-continued.md#2026-11-14-登记测试群现场-http-回读通过)、
  [普通文本入站修复](../execution/2026-11-13-snowcat-capability-integration-continued.md#2026-11-14-普通文本入站现场与空提及字段适配)
  与[双账号 LoginInfo](../execution/2026-11-13-snowcat-capability-integration-continued.md#2026-11-14-新代次双账号-logininfo-现场)。

因此“身份与持久 OneBot ID 查询一致”在指定固定构建样本上已有现场证据；本文不把它外推到任意
QQ 版本、任意账号或 CPB/native 响应身份。

## 3. 本轮补充的传输证据

### 3.1 协议矩阵

新增于 [onebot_transport.rs](../../crates/caligo-core/src/onebot_transport.rs) 的单元测试（真实回环 socket）：

- `forward_websocket_enforces_auth_paths_roles_and_echo`：错误 token 握手 401、未知路径 404；
  `/api` 只返回动作响应且不接收事件；`/event` 只推事件且不回复动作；`/` 双向；
  `echo` 为任意 JSON（对象/嵌套数组）时原样返回；`get_version_info` 的 `protocol_version=v11`。
- `reverse_websocket_reconnects_after_application_close_and_delivers_again`：两次连接的
  `X-Self-ID`/`X-Client-Role: Universal`/Bearer/User-Agent 头均匹配；应用侧正常 close 后客户端按间隔重连，
  第二连接的动作 echo 与事件继续可用。
- 既有回归继续覆盖 HMAC-SHA1 签名与 204、POST→WS 的顺序、快速回复只走共享动作层、
  非法路径/角色不复制动作逻辑。

### 3.2 慢连接与丢失可见性

- `stalled_websocket_writer_does_not_block_publish_and_drop_count_is_visible`：用一个首帧即阻塞的
  transport writer 替代真实慢客户端，向有界队列发布 512 条事件。发布路径保持非阻塞
  （断言小于 2 秒），该订阅者的丢弃计数大于 0；释放 writer 后可正常停止。这补的是
  “写端阻塞时 fanout 不被拖住、丢失被计数”的确定性合同。
- `http_post_failure_still_forwards_the_event_and_reports_loss`：POST 端返回 500 时，
  事件仍向 WS 订阅者 fanout，worker 的 `delivered` 不把失败计为成功。
- 运行期可观测性：正向/反向 WS 断开或关闭时输出 `dropped events=N`；HTTP POST 停止时若有
  失败或队列丢失，输出 `delivered/failed/dropped`。计数来自每个 transport 独立的
  `EventBus::subscriber_dropped`，不消费事件，也不阻塞 native 事件受理路径。
- 边界：Windows loopback 会吸收真实 socket 背压（2026-11-13 SSE 实验记录：32 MiB 与 4 KiB
  socket buffer 尝试都未在期限内制造溢出），因此本轮**不**把“真实 TCP 慢客户端”记为已通过。
  真实慢客户端与第三方应用的现场矩阵仍需单独准入。

   并调用一次 `get_msg` 与一次发送；核对同一消息的 request/native/event/store 链。
3. 慢连接矩阵：应用停止读取或断开 WS，确认其他 transport 仍可用、丢失计数/断开日志可读，
   恢复后不重发 unknown 请求。
4. 停止与清理按现有合同执行；任何 unknown 不重发、不热卸载，原始材料只进 ignored
   `local-evidence/`。
