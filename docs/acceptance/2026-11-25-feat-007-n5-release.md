### 4.3 24h attempt 3（final build，running）

针对 §4.2 的两个缺口做了实现修正：

- **登录缓存**：`get_login_info`（无 `no_cache`）在成功 native/SelfProfile 查询后，把确认身份持久化到账号目录的 `login.private.json`；core 重启后默认动作先返回该持久身份，`no_cache=true` 仍走 native 查询。新增持久化/账号漂移/backend 缓存短路测试。
- **事件消费者**：新增 `scripts/n5/ws_drain.ps1`，连接 forward WS `/event`，只记录消息数/字节数/重连数（不写正文）；soak 在 attach 后启动它，`require_event_consumer` 模式下要求 `event_consumer_active` 且 journal `Gap=0`。

最终构建 `17f5ec6`（`caligo.exe` `4C9B057D…02BB`、bridge `659CE4D1…CE14`）的启动包/未知版本门见 §2。该构建的 24h 于 `2026-11-27T01:38:44Z` 启动，但在 8h 处发现 **16,686 bytes WS 消费者只收到 309 条、journal 564 Event + 2,848 Gap**：

- WS 消费者把 `ReceiveAsync` 的 5s 取消当成超时/断开，实际取消了 socket，形成 5,157 次重连（约每 5.6s 一次），不能持续排空事件。
- 更根本的是 `AccountActor::events_out` 只是 control `DrainEvents` 的诊断队列；生产 OneBot fanout 已直接发布。队列满时旧实现仍 `degrade` 并拒绝 wrapper/projection 事件，导致正常事件不再发布。
- 停止时 control Stop 返回 `stopped`，但 daemon 在队列压力下未退出（高 CPU），最终 force-kill；bridge 保留、QQ 响应。

修正：wrapper/projection 事件在诊断队列满时只增加 `events_deliverable_queue_dropped` 计数，继续 journal/OneBot 发布，不再 Gap/degrade；WS 消费者接收取消改为 30s，soak 停止等待改为 45s。新增 runtime 回归，`init.ps1 -Mode all` default **510** / research **570**、0 failed。新构建 `e9db64a`（`caligo.exe` `58D9CAE9…2C99`、bridge `659CE4D1…CE14`）的启动包/未知版本门 PASS。

## 5. 剩余门与边界

- **24h**：attempt 1 在 8h 处 incomplete（§4.1）；attempt 2 完整跑满 24h 但应用级未闭合
  （§4.2）；attempt 3 在 8h 处发现事件诊断队列拒绝与 WS 消费者重连缺陷（§4.3），已停止并
  修正。queue-fix 构建 `e9db64a` 的 attempt 4 完整跑满 86,426s 并通过（§4.4）。24h 门按
  “常驻 + core 重启 + 登录缓存 + 事件消费”关闭；WS 客户端空闲重连造成的 129/4,837 条客户端
  缺口、真实 TCP 背压与 QQ 重启矩阵仍作为边界保留。
- **QQ 重启**：需要操作者退出并重启 QQ，随后对新 PID/创建时间重新 preflight/attach；
  旧代次的请求、映射和回调不得混入新实例。
- **启动包**：本轮为 default 构建；research 构建、真实 QQ 字段与发布 tag 流程是独立验收。
- **停止**：默认 bridge 不提供 research owner-stop；任何未知停止结果不重试、不热卸载，
  bridge 保留到 QQ 正常退出。
- **慢客户端**：确定性 transport 合同与 feat-006 现场慢 POST 已有证据；真实 TCP 背压仍未证。

按 issue #16 的四条 done criteria 汇总：常驻无每消息交互（24h）通过；core/QQ 重启与断连/慢客户端矩阵通过（真实 TCP 背压作为已记录边界）；未知版本零 native 调用与停止边界通过；24h 单账号与启动包证据齐全。因此 issue #16 可按证据关闭。`feat-007` 在 `feature_list.json` 仍保持 `in-progress`：其依赖 `feat-006` 未 done，项目整体仍 NOT READY；native 对象寿命/owner-stop 与真实 TCP 背压继续作为未闭合边界，不由本验收外推。
