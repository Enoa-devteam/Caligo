## 4. 2h 现场观察（issue #16 第 2 项）

现场包在 ignored `local-evidence/feat007-n5-20261125-unbound/`。目标为最后启动的新 QQ 主根
（PID 见包内 `state.private.json`，登录登记账号 B），通过只读 preflight：固定 manifest/模块
哈希、PE/backend 审计、唯一 Environment、无已映射 bridge、端口唯一。

流程：一次 `cli qq-entry` attach → 60s 周期 `get_version_info`/`get_status`/`get_login_info`
→ 在 30/60/90 分钟各注入一次 core 崩溃（kill），同 journal/pipe/token 重启并等待 bridge
重连 → 结束控制停止。**零消息发送**；该账号期间收到 495 条真实入站事件，正文/身份只留在
本机 ignored 目录，仓库只保留计数与哈希。

### 4.1 24h attempt 1（2026-11-25T14:56:45Z–23:00:15Z，incomplete）

在另一个新 QQ 主根上启动 24h soak（零发送、60s 探测、+2h/+8h/+16h 重启）：

| 项目 | 结果 |
|---|---|
| 运行 | 479 个采样、约 8h 后 harness 主动终止；version/status 探测 958/958 成功（`retcode=0`），但 `get_login_info` 从 `15:19:49Z` 起持续返回 1502，共 456 次 |
| 入站链 | journal 从 0 增至 4,409,381 bytes；第一次重启后 journal 继续增长，说明 bridge/core 仍在接收事件 |
| 重启 | 第 1 次（`16:56:46Z`）1.5s 恢复且登录查询短暂成功；第 2 次（`22:56:46Z`）daemon 启动、journal 继续增长，但 `get_login_info` 在 188s 内超时，harness 将其判为 fatal 并停止 |
| 停止 | control Stop exit 0，daemon 退出（进程码 1），默认 bridge 保留、QQ 响应；未重试、未重新 attach |
| 结论 | **24h 门未通过**。不能把“登录查询 1502”单独解释为常驻链失败：version/status 与 journal 增长显示事件链仍工作；但 24h 样本没有闭合 |

harness 的两个判据被证明不合适：`get_login_info` 在 QQ 锁屏/会话不可用时诚实返回 1502，
不应计入 version/status 探测失败；core 重启恢复也不应以登录查询为唯一信号。`n5_soak.py`
已改为：version/status 作为恢复与 `probes_answered` 信号，登录查询单独计数并保留 1502；
attach 时仍要求一次登录成功。该修复通过离线 rehearsal（18s，含一次 core 重启）。

## 5. 剩余门与边界

- **24h**：2h 观察只覆盖短时恢复；`CoreStopped` 后默认 bridge 的 daemon worker 已退出，
  同一 QQ 代次不能重新 attach。24h attempt 1 在 8h 处 incomplete（§4.1）：version/status
  与 journal 链持续，但 `get_login_info` 因 QQ 锁屏/会话不可用长期返回 1502，harness 误把它
  当作探测失败/重启恢复信号。判据已修正，需要在新的新鲜 QQ 代次上重跑完整 24h；重跑通过前
  不把该门标为通过，也不关闭 issue #16。
- **QQ 重启**：需要操作者退出并重启 QQ，随后对新 PID/创建时间重新 preflight/attach；
  旧代次的请求、映射和回调不得混入新实例。
- **启动包**：本轮为 default 构建；research 构建、真实 QQ 字段与发布 tag 流程是独立验收。
- **停止**：默认 bridge 不提供 research owner-stop；任何未知停止结果不重试、不热卸载，
  bridge 保留到 QQ 正常退出。
- **慢客户端**：确定性 transport 合同与 feat-006 现场慢 POST 已有证据；真实 TCP 背压仍未证。
