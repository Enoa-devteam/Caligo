# feat-005 路线适用性与完成门（2026-11-21）

本文件确定 feat-005（N3 常驻 native 链路验收）的当前范围：哪些历史原生结论适用于现行正式 bridge，
哪些属于研究资产，以及三条完成条件各自已有和仍缺的证据。本文是范围判定与取证计划，**不是现场准入**，
也不改变任何能力状态。本轮未接入 QQ、未发送消息。

## 1. 两条路线

| | 正式路线（生产） | 历史原生路线（研究） |
|---|---|---|
| 入口 | `caligo_qq_entry_bootstrap` → `qq_entry::bootstrap` → owner pump / V8 阶梯 | 历史 `g1/g2/g3/g3-session/obs/async/exec` 导出与 `caligo_native_resident_run` |
| 适配器 | `QqOwnerAdapter`（[qq_entry.rs](../../crates/caligo-bridge/src/qq_entry.rs)），`Resident<QqOwnerAdapter>`（[lib.rs](../../crates/caligo-bridge/src/lib.rs)） | `NativeHostAdapter`、`native_msf`/`native_session`/`native_response`/`g3_ops` |
| 收发 | V8 wrapper `sendMsg`/Promise/精确回读、D8 push、`qq_query` 固定 wrapper 查询 | MSFService 原生提交、consumer 响应 UID、CPB 解码 |
| 默认构建 | 唯一创建常驻链路的入口 | 导出存在但首语句 `gate::reject_legacy()` 拒绝（0xE0）；`native_resident`、`g3_send_run_9936`、`consumer_probe` 等只在 research 编译 |
| 共享部分 | `Resident`、IPC/worker、core actor/journal/message_store、OneBot 出口 | 同上，经 `NativeHostAdapter` 接入 |

依据：[lib.rs](../../crates/caligo-bridge/src/lib.rs) 的 `#[cfg(feature = "research")]` 模块与导出、
[gate.rs](../../crates/caligo-bridge/src/gate.rs) 的 D0 门控、[Cargo.toml](../../crates/caligo-bridge/Cargo.toml) 的
`default = []`，以及 `qq_entry.rs`/`qq_query.rs`/`resident.rs` 中没有对 `native_msf`、`native_session`、
`native_response`、`g3_ops`、`consumer_probe` 的引用。历史 K4 路线决定（原生 MSF/SSO）见
[原生路线决定](../research/k4-native-route-decision.md)；该决定早于正式 bridge 统一，其“V8 路线降为备选”的
结论已被 2026-11-15 起的正式 bridge 实现取代，旧决定的准入与禁用边界仍作为研究路线约束保留。

## 10. 2026-11-21 在途请求核心重启离线回归

新增 `core_restart_query_lab::inflight_send_across_core_restart_is_not_redispatched`：

- 合成 owner 在 `HostOp::SendText` 内阻塞，保证派发已到达 worker、native 调用已开始，但 `NativeStarted` 尚未产生；此时 core journal 只应有 `Queued → DispatchIntent`。
- 终止 core #1 后，用同一 journal/pipe/token 启动 core #2；随后释放 owner。worker 的断开清理需要 owner 持有的 adapter 锁，所以释放发生在启动新 core 之后、等待 HelloAck 之前。
